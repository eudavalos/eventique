## 🧭 RESUMEN EJECUTIVO

Eventique es una plataforma multi-tenant de invitaciones digitales con una arquitectura sólida
(React + FastAPI + SQLite + Cloudflare Tunnel), una propuesta visual elegante y un panel de
administración bien estructurado en concepto. Sin embargo, la auditoría revela **10 hallazgos
críticos** que comprometen la funcionalidad core, la seguridad y la confianza del cliente.

Los tres problemas más graves son:
1. **Bug de routing RSVP**: todos los RSVPs se registran en el evento `default` ignorando el
   `event_slug` — pérdida total de datos de confirmación de asistencia.
2. **Exposición de tokens en la API**: el endpoint `/api/events` devuelve admin tokens en texto
   plano — brecha de seguridad de nivel OWASP A02.
3. **Todas las imágenes rotas**: 20 imágenes apuntan a `/photos/` (ruta inexistente) en lugar
   de `/uploads/` — la invitación está completamente sin contenido visual.

Adicionalmente, se detectaron inconsistencias de datos críticas (fechas duales, nombres de
placeholder), errores funcionales en el admin (TOKEN generation falla, formularios sin validación,
modal no cierra con ESC) y múltiples problemas de accesibilidad y UX.

**Recomendación:** Detener deployment en producción hasta corregir los hallazgos P0 y P1.

#### H-001 · Admin tokens expuestos en texto plano via API
| | |
|---|---|
| **Tipo** | Seguridad |
| **Severidad** | 🔴 Crítico |
| **Prioridad** | P0 |
| **Área** | Backend API |

**Descripción:** `GET /api/events` (autenticado con superadmin token) devuelve el campo
`admin_token` en texto plano para todos los eventos en la respuesta JSON. Ejemplo verificado:
`{"admin_token": "token-boda-concepcion-eumelio", ...}` para cada evento en el listado.

**Impacto usuario:** Cualquier persona con acceso al superadmin token puede obtener los tokens
de todos los event admins y tomar control de cualquier evento.

**Impacto negocio:** Violación de confidencialidad en sistema multi-tenant. Si el superadmin
token se compromete, TODOS los eventos quedan expuestos. Incumplimiento GDPR/datos personales.

**Recomendación:**

```python
# En el modelo de respuesta, excluir el token
class EventResponse(BaseModel):
    id: int
    slug: str
    name: str
    created_at: datetime
    # admin_token: str  ← NUNCA exponer

# Hashear tokens en BD
import bcrypt
hashed_token = bcrypt.hashpw(token.encode(), bcrypt.gensalt())
```
1. Eliminar `admin_token` de TODAS las respuestas de la API.
2. Hashear tokens en la base de datos (bcrypt/argon2).
3. Crear endpoint separado `POST /api/events/{slug}/rotate-token` para regeneración.
4. Implementar auditoría de accesos con timestamps.

**Justificación:** OWASP Top 10 A02:2021 — Cryptographic Failures. Secretos en texto plano
son una vulnerabilidad crítica en cualquier sistema multi-tenant.

#### H-002 · XSS Stored — API acepta HTML y scripts sin sanitización
| | |
|---|---|
| **Tipo** | Seguridad |
| **Severidad** | 🔴 Crítico |
| **Prioridad** | P0 |
| **Área** | Backend API + Frontend |

**Descripción:** El endpoint `POST /api/rsvp` acepta y almacena payloads HTML/JS sin sanitizar.
Verificado: `{"name": "<script>alert(1)</script>XSS Test", ...}` fue almacenado exitosamente
con el script intacto. Si el admin panel renderiza este nombre en el tab RSVPs sin escapar,
el script se ejecutará en el contexto del administrador.

**Impacto usuario:** Ejecución de scripts maliciosos en el navegador del admin.

**Impacto negocio:** Robo de sesión, toma de control del panel admin, inyección de contenido
malicioso en invitaciones. En un sistema multi-tenant, puede propagarse entre eventos.

**Recomendación:**
```python
# Backend: sanitizar con bleach
import bleach
def sanitize_text(text: str) -> str:
    return bleach.clean(text, tags=[], attributes={}, strip=True)

class RSVPCreate(BaseModel):
    name: str = Field(min_length=2, max_length=100)
    
    @validator('name')
    def sanitize_name(cls, v):
        return bleach.clean(v, tags=[], strip=True)
```
```tsx
// Frontend React: siempre usar texto, nunca innerHTML
<td>{rsvp.name}</td>  // ✅ React escapa automáticamente
// NUNCA: <td dangerouslySetInnerHTML={{__html: rsvp.name}} />
```
3. Añadir Content-Security-Policy headers en nginx.
4. Validar todos los campos de texto con regex que rechacen caracteres HTML.

**Justificación:** OWASP Top 10 A03:2021 — Injection. XSS stored en admin panel es
una vulnerabilidad de alta severidad que puede llevar a compromiso total de la cuenta.

#### H-020 · Animaciones de scroll-reveal desincronizadas
| | |
|---|---|
| **Tipo** | UX / Performance |
| **Severidad** | 🟡 Medio |
| **Prioridad** | P3 |
| **Área** | Invitación — Global |

**Descripción:** Las animaciones de entrada con opacity se activan tarde. Al scrollear
rápidamente, el contenido aparece en estados intermedios (20-30% de opacidad) mientras
el usuario ya está leyendo. El threshold del IntersectionObserver parece ser ≥0.5,
causando que las animaciones inicien cuando el elemento ya está a la mitad del viewport.

**Recomendación:**
1. Reducir threshold a `0.1` para iniciar animaciones antes.
2. Reducir duración de 1000ms → 400ms para mayor snappiness.
3. Implementar `prefers-reduced-motion`:
```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```
4. Asegurar que el contenido sea legible sin JavaScript activo.
